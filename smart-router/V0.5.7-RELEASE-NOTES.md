# Hermes Smart Router v0.5.7 Release Notes

v0.5.7 integrates execution governance into Hermes Operations Center without collapsing the independent execution-approval security boundary.

## Highlights

- new **Execution & Approvals** workspace in Operations Center;
- direct browser connection to a separate optional Execution Admin service;
- separate, non-persisted Execution Admin credential;
- live Sandbox/Docker/SSH policy enable/disable for already-deployed brokers;
- numeric Telegram execution-approver management constrained by host-approved Telegram users;
- write-only approval-bot token replacement;
- broker control-secret rotation and execution-admin audit view;
- broker/approver health and SSH profile metadata display;
- live policy-generation and feature files so policy changes take effect without stale environment state;
- every mutation bumps policy generation, invalidating older pending grants;
- Smart Router schema marker advances in place to `0.5.7` while retaining the `control-v0.5.2.sqlite3` compatibility filename;
- v0.5.6 platform features and light/dark UI retained.

## Security boundary

The Execution Admin service has no Ed25519 approval private key, Docker socket, or SSH private credential mount. Smart Router does not receive the Execution Admin key or Telegram approval-bot token. First-time broker deployment and SSH credential lifecycle remain host operations.

## Companion image

Use Hermes Execution Broker `0.1.2` with this release and pin the published multi-architecture manifest digest for production.
